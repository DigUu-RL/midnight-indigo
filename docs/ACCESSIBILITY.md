# Accessibility

> Generated by `npm run audit:accessibility` from the eight theme files, and held by `npm run check`. Do not edit it by hand. [Versão em português](ACCESSIBILITY.pt-BR.md).

Midnight Indigo is an ultra-dark theme meant for long sessions. This page measures every pair the theme is responsible for, in all eight variants, against targets that are the theme's own and are enforced: a variant that misses one does not pass the check.

## Targets

| Target |  |
| --- | --- |
| **body 7:1** | The code, and the text it is written among: WCAG AAA. Read for hours, so held to the highest bar. |
| **text 4.5:1** | Any other text — menus, buttons, the terminal, chat — and the type parameters: WCAG AA. |
| **auxiliary 3:1** | Text designed to recede: comments, CodeLens, inlay hints, placeholders, line numbers. Still readable; never competing with the code. |
| **component 3:1** | What is seen rather than read: a squiggle, a focus ring, an icon. WCAG 1.4.11. |
| **exempt** | Disabled controls and rendered whitespace, which WCAG leaves out on purpose. Measured here, not held. |

## Without colour

Nothing critical depends on seeing a hue. These hold in every variant, and the check fails if one stops holding:

- Keywords are bold italic, so the most frequent role is told apart by its letterforms too.
- A deprecated name is struck through: `*.deprecated` from a language server, `invalid.deprecated` from a grammar. VS Code strikes through a name a diagnostic marks deprecated (TypeScript, C#) by itself.
- Focus is a solid ring (`focusBorder`, `list.focusOutline`), never a translucent tint that could vanish into what it sits on.
- A selection changes the surface: the editor, list and terminal selections are each at least 3 ΔE from the ground under them.
- Error, warning and info differ in lightness as well as hue (at least 0.05 in OKLCH L), so they separate on a greyscale screen.

### Colour vision

The signals that do differ by hue, simulated for the three common deficiencies (Machado et al., 2009, full severity) and measured in OKLab ΔE × 100 — about 2 is the smallest difference anyone notices side by side. A pair with no other cue is held to 10; a pair VS Code also tells apart by a shape or a letter is held to 3. Each cell is the worst of the eight variants.

## Environments

A screen at half brightness, modelled as doubling the flare WCAG assumes (see the source for why this is a model and not a measurement). The pairs with the least room:

| Pair | Full | Half |
| --- | ---: | ---: |
| Body text on the editor | 7.0 | 4.0 |
| Comments on the editor | 4.0 | 2.5 |
| Type parameters on the editor | 4.5 | 2.8 |
| Line numbers | 3.0 | 2.0 |

On OLED, the editor ground is never `#000000`, but its brightest channel is a few steps above zero, so most of it is close to switched off: fast scrolling can smear there, as it can with any ultra-dark theme. That is the identity, not a defect this audit tries to fix. What a dim panel can also crush is a near-black ground that has to be seen against the editor; each is shown here as its distance from the editor in ΔE:
