# Syntax

> Generated by `npm run inventory` from the built themes, [`tools/syntax/syntax-corpus.ts`](../tools/syntax/syntax-corpus.ts) and [`tools/syntax/semantic.ts`](../tools/syntax/semantic.ts). Do not edit it by hand.

What code is drawn in. Every rule below writes a role from [`docs/TOKENS.md`](TOKENS.md#syntax) — never a colour — so the tables hold in all eight themes; TOKENS.md lists what each role is in each family. **Keywords are bold italic**, in every theme and every language; punctuation is the keyword colour, plain; operators are the operator colour and nothing else.

`npm run check` holds all of it to real code: [`tools/syntax/check-syntax.ts`](../tools/syntax/check-syntax.ts) tokenizes 29 files with the grammars VS Code ships, in all eight themes, and checks every word the corpus below names, every keyword, operator and punctuation mark in every file, and that no scope that names something falls through every rule to plain text. TypeScript is checked with semantic highlighting off and on — its semantic tokens come from the TypeScript language service and are resolved the way VS Code resolves them — and the other language servers from the table of the tokens they send.

## Where no theme can decide

- **C# methods are drawn the same declared and called.** Roslyn sends no `declaration` modifier, so with semantic highlighting on both are plain; the C# grammar scopes both `entity.name.function.cs`, so without it both are bold.
- **Names a grammar does not scope** — Python imports and annotated fields, Java locals, most of Kotlin, unqualified SQL names — are body text until a language server names them.
- **A React component is drawn as what it is declared as.** A component tag — `<Avatar />` — is the class colour; a function component is a function where it is declared and a class component a class. Until M9 a grammar injection marked a capitalised function as a component, and in doing so took its `export`, `default` and `function` away from the keyword rule; TypeScript's semantic tokens drew the name as a function all the same, so the injection was only ever visible as the bug.
- **`const` as a `type`.** TypeScript sends the `const` of `as const` as a type, so VS Code draws it as one, in every theme.
